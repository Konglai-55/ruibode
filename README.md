# 美国机器人教育与竞赛基金会（RECF）授权上海瑞卜德教育科技有限公司赛事报名平台

面向机器人赛事的完整报名系统原型，覆盖普通用户、战队资料、赛事报名与管理员审核。项目使用 Node.js 24 内置 HTTP 与 SQLite 实现，不依赖第三方运行时包，解压后即可启动。

## 已实现功能

- 页首登录、注册、图形验证码、邮箱验证码与登录后用户菜单；注册保存用户名、昵称、邮箱及手机号，用户可使用用户名或邮箱配合密码直接登录
- 首页已内置为站内页面，复刻官网首屏、报名引导、竞赛类目与合作伙伴展示；导航栏与底栏沿用报名平台设计，不再跳转到外部首页
- 通过注册邮箱验证码找回密码；验证码单次使用、最多尝试 5 次，重置成功后旧会话全部失效
- 个人资料、密码、头像、身份证号及单位资料维护
- 队员与教练的新增、编辑、查看和删除；必填项与图片校验
- 战队新增、编辑、查看和删除；教练最多选择两名、选满后锁定其余选项，联系人限定为已选教练
- 默认提供 RECF-Achieve、RECF-Engage 与 RECF-Inspire 的常用参赛组别，管理员可在赛事中新增未来赛季组别；5 个已知创新组自动添加对应 `RECF-*` 前缀，并校验最终战队编号为 1–30 个 ASCII 字符且全局唯一
- 赛事列表、详情、报名时段、参赛组别、战队确认、缴费信息与凭证上传
- “我的比赛”状态跟踪、详情查看、待审/驳回记录编辑和删除；已取消参赛记录仅可在报名期内且比赛开始前重新申请参赛，同一战队同一赛事最多提交 2 次退费申请
- 志愿者与观赛报名、个人申请记录、驳回后修改重提及管理员审核；每场赛事可分别控制是否开放，默认关闭
- 管理员发布/编辑赛事、上传海报、可视化编辑办赛通知、设置附加报名入口并审核各类报名；赛事报名审核通过或驳回后自动邮件通知战队教练，审核页支持关键词搜索，已通过与已驳回记录可再次调整状态
- 办赛通知正文为选填项，管理员可在正文中插入或粘贴 JPG、PNG、WebP 图片并上传、替换或移除 PDF；前台将正文图片正常展示，PDF 自动嵌入正文下方，正文为空时也可单独展示 PDF
- 管理后台可按用户名、昵称、邮箱、战队编号/名称、教练员或学生姓名搜索用户，并查看账户、战队、参赛赛项、教练员与学生完整资料
- 管理后台可跨账号搜索并查看已有战队、所属用户、教练、队员及累计报名资料
- 赛事报名数据可按全部、审核通过、取消参赛分别导出，均按参赛组别生成 Excel 工作簿并合并为 ZIP；表格中的“报名取消”列专指用户自行取消比赛的状态、原因与时间
- 已结束赛事自动移出管理员审核工作台和待审统计，但报名数据不会删除，用户历史记录继续保留
- 桌面端与移动端响应式布局、无横向溢出、键盘焦点和 reduced-motion 支持
- HttpOnly 会话、CSRF、防暴力请求限速、Scrypt 密码哈希、CSP 与上传大小限制

## 本地运行

需要 Node.js 24 或更高版本。

```powershell
npm start
```

打开 `http://127.0.0.1:3000`。

演示账号：

- 普通用户：`demo@ruibude.local` / `Demo123!`
- 管理员：`admin@ruibude.local` / `Admin123!`

数据默认保存在 `data/app.db`，上传文件保存在 `data/uploads/`。首次启动会自动创建数据库并写入演示赛事与资料。

## 环境配置

可参考 `.env.example` 设置环境变量：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 端口 |
| `HOST` | `127.0.0.1` | 监听地址 |
| `NODE_ENV` | `development` | 设为 `production` 后启用生产环境邮件行为与安全 Cookie |
| `DB_PATH` | `data/app.db` | SQLite 数据库路径 |
| `ADMIN_EMAIL` | 空 | 生产环境空库首次启动时创建管理员，必填 |
| `ADMIN_PASSWORD` | 空 | 生产环境空库首次启动时创建管理员，至少 12 位 |
| `EMAIL_WEBHOOK_URL` | 空 | 可选：接收 `{to, subject, text, html}` JSON 的邮件服务 Webhook |
| `SMTP_HOST` / `SMTP_PORT` | `smtp.exmail.qq.com` / `465` | 可选：使用腾讯企业邮箱 SMTP 发信 |
| `SMTP_USER` / `SMTP_PASS` | 空 | SMTP 发件邮箱与邮箱后台生成的 SMTP 授权码 |
| `SMTP_FROM` / `SMTP_FROM_NAME` | 同发件邮箱 / 平台名称 | 邮件中显示的发件地址与名称 |

只有测试环境，或开发环境尚未配置邮件传输时，接口才会返回仅供本地调试的验证码；一旦配置 SMTP/Webhook，验证码只通过真实邮件发送，不会自动填入页面。图形验证码本身始终以不可直接提取文字的像素图形显示。登录与密码重置验证码有效期为 10 分钟、仅可使用一次，连续输错 5 次后必须重新获取。生产环境必须配置 `EMAIL_WEBHOOK_URL` 或完整的 SMTP 参数，否则不会泄露验证码并会提示邮件服务未配置。项目启动时会自动读取根目录中已被 `.gitignore` 排除的 `.env`；不要把 SMTP 授权码提交到代码仓库。生产环境不会创建演示账号或示例赛事，空库首次启动还必须提供管理员环境变量。

## 验证

```powershell
npm test
npm run visual-check
```

API 测试使用独立临时数据库和上传目录，结束后自动清理。视觉验收会自行启动临时服务，检查桌面/移动赛事、志愿者、观赛、战队及管理员审核页面，并把截图保存到 `artifacts/visual-check/`。

## 上线前清单

- 开发库中的演示账号只用于本机验收；生产环境使用 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 初始化独立管理员。
- 通过 HTTPS 反向代理对外提供服务，并将 `HOST` 保持为内网监听地址。
- 配置真实邮件 Webhook、日志、监控、数据库定时备份及上传文件备份。
- 当前内存限流适合单实例部署；扩展为多实例时，应在网关或 Redis 中统一实施登录、验证码与上传限流。
- 根据实际隐私政策决定身份证等个人信息的保存期限、访问审计与加密方案，并取得必要授权。
- 上传文件默认按所有者保护；赛事海报与通知仅在已发布赛事引用后公开。仍应为历史孤儿文件配置定期清理任务。
- 将示例收款资料、赛事内容、战队编号说明和通知文件替换为主办方正式内容。
